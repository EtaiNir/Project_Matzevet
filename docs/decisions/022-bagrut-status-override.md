## ההחלטה

1. **מי:** מנהל־על, ורכז/ת בגרויות (כולל מנהל/ת בית ספר), בתלמידים שהם רואים.
   "האנשים עם ההרשאות שדיברנו עליהם" הם אותם אנשים שהוגדרו לעריכת ציונים ב-20.10.
   ההרשאה נאכפת במסד (`may_override_bagrut_status`), לא רק בכפתור.
2. **מה:** זכאי ↔ אין זכאות, לתלמיד בשכבה המסיימת (שיש לו ניתוח זכאות). שני
   ערכים בלבד, כמו שאייל ביקש. "שלילי אחד" נשאר כפי שקבע ניתוח הזכאות.
3. **סיבה חובה.** נשמרים מי, מתי ולמה. הטבלה היא יומן: כל שינוי מוסיף שורה, ואין
   עדכון ואין מחיקה. כך ההיסטוריה המלאה נשמרת.
4. **ניתוח הזכאות אינו משתנה.** השינוי יושב בטבלה נפרדת (`bagrut_status_overrides`),
   והמסך מחיל אותו מעל הניתוח. "חזרה לניתוח הזכאות" היא לחיצה אחת. במסך מוצג גם
   מה קבע הניתוח, והתג מסומן ✎.
5. **כל מה שנגזר מהסטטוס מחושב מחדש** — כולו נספר בדפדפן דרך `eligibilityKind`:
   - אחוזי הזכאות של השכבה ובית הספר (תמונת המצב, האזור האישי)
   - בגרות מצטיינת, טק וטק בלי אנגלית
   - "על הסף", "אין זכאות" בסרגל
   - רשימות התלמידים והייצוא לאקסל (עם "(שונה ידנית)")

   לכן לא נשמר עותק של האחוזים, ואין מה שיתיישן. **כל קוד חדש שקורא סטטוס זכאות
   חייב לעבור דרך `eligibilityKind`**, ולא לפענח את `s.status`.
6. **השינוי נמחק בקליטת הסבב הבא** (cascade עם הסבב). הקבצים החדשים הם ניתוח
   חדש, ואם השינוי עדיין נכון צריך לעשות אותו שוב. כך נהגו גם העריכות של 018.

## איפה נשמר

בטבלה **`bagrut_status_overrides`** ב-Supabase (מיגרציה 043) — **לא** ב-`bagrut_students`:

| עמודה | מה |
|-------|----|
| `round_id` + `student_id` | הסבב והתלמיד. `round_id` — `on delete cascade`: קליטת סבב חדש מוחקת |
| `kind` | `eligible` (זכאי) / `not_eligible` (אין זכאות). **ריק = חזרה לניתוח הזכאות** |
| `reason` | הסיבה. חובה כש-`kind` מלא (`check` בטבלה) |
| `set_by` / `set_by_email` | מי שינה. `on delete set null` (מלכודת 24); האימייל משוכפל כדי לשרוד מחיקת משתמש |
| `set_at` | מתי — `clock_timestamp()`, כדי ששני שינויים באותה טרנזקציה יישמרו בסדר הנכון |

- **יומן, לא שורה לתלמיד:** כל שינוי — שורה חדשה. **התקף = האחרון לפי `set_at`.**
  אין עדכון ואין מחיקה, ולכן ההיסטוריה המלאה נשארת: מה היה, מי שינה, מתי, ולמה.
- **קריאה** (RLS): מי שרואה את התלמיד ב-`bagrut_students`. **כתיבה:** רק דרך
  `bagrut_set_status(p_round, p_student, p_kind, p_reason)` — security definer;
  אין מדיניות insert/update/delete (insert זורק, update/delete — 0 שורות, מלכודת 21).
- **הפונקציה בודקת:** הרשאה (`may_override_bagrut_status`), שהתלמיד בשכבה המסיימת
  (`in_t2`), סטטוס מוכר, וסיבה. אותו מצב ואותה סיבה — לא נרשם (`changed: false`).
- **במסך:** `loadRound` טוען את היומן, לוקח את האחרון לכל תלמיד, ומצמיד אותו
  ל-`student.override`. `eligibilityKind` מחזירה אותו לפני ניתוח הזכאות;
  `analysisKind` — מה שהניתוח קבע, להצגה לצדו.
